# Options Income Trade List Generation — Task Definition

> Conventions: This task follows the rules defined in [task-conventions.md](task-conventions.md). Read that file before creating or modifying any task document.

This file defines the standard task for running the Options Income Agent. It records the canonical prompt, pre-flight checks, agent guidelines, data collection method, and output conventions.

When this task is executed, the agent must follow the steps below in order. Do not skip pre-flight checks.

---

## Standard Prompt

> "Generate an options income trade list using the current macro regime and available candidate stocks."

Before proceeding, the agent must present this prompt to the user and ask:

> "This is the standard prompt for this task. Do you want to use it as-is, add to it, or replace it with a different prompt before I continue?"

Wait for confirmation before moving to the pre-flight checks. If the user provides additions or a new prompt, record it and proceed with the modified version.

---

## Pre-Flight Checks

Complete all checks before generating any output. If any check fails, stop and surface the issue to the user.

### 1. Output File Frontmatter Standard

All output files generated by this task must include the following frontmatter fields:

```yaml
---
date: "YYYY-MM-DD"
time: "HH:MM"
generated_by: "Options Income Agent"
inputs_used:
  - context/trading-agent/output/macro-outlook.md (date: YYYY-MM-DD)
  - context/trading-agent/output/value-stock-list.md (date: YYYY-MM-DD)  # if used
---
```

Both `date` and `time` are required.

### 2. Input File Freshness Check

Before consuming any input file, check its `date` frontmatter field against today's date.

Files to check:

| File                  | Required | Freshness Rule          | If Missing                                                      |
| --------------------- | -------- | ----------------------- | --------------------------------------------------------------- |
| `macro-outlook.md`    | Yes      | Must be 7 days or newer | Stop. Ask user to run the macro outlook task first.             |
| `value-stock-list.md` | No       | Must be 7 days or newer | Proceed without it; note candidates were sourced independently. |

If `macro-outlook.md` is older than 7 days, stop and ask:

> "macro-outlook.md was last generated on [date], which is more than 7 days ago. The market regime call drives the strategy defaults for this task. I recommend regenerating it first. Would you like me to do that, or proceed with the existing file?"

If `value-stock-list.md` exists and is fresh, use it as the primary candidate source. If it is stale or missing, source candidates independently from Finviz and Yahoo Finance using the criteria in the Data Collection section below.

### 3. Finviz Authentication Check

Before any data collection step, follow the Finviz authentication protocol defined in task-conventions.md Section 7. Ask the user:

> "Do you have a Finviz Elite login? If so, I can gather significantly more complete data — particularly IV rank, full options data, and earnings dates. What is your preferred approach for authenticated access?"

Authenticated access is especially important for this task because IV rank and IV percentile are not available on the public Finviz version and are critical inputs for selecting premium-selling entries.

### 4. Earnings Date Confirmation

For every candidate selected for an undefined-risk (naked) options position, confirm the next earnings date before specifying any trade. If an earnings event falls within the proposed DTE window, the agent must either:

- Reduce the position to a defined-risk spread that caps the loss through the event, or
- Explicitly note the binary event risk and let the user decide whether to proceed.

Do not specify an undefined-risk short put on a name with earnings inside the DTE window without surfacing this risk.

## Agent Guidelines

Source file: [trading-options-income-agent.md](trading-options-income-agent.md)

### Agent Identity
- **Agent Name:** Options Income Agent
- **Role:** Options-income analyst generating cash flow from high-quality stocks using defined and undefined-risk premium-selling setups
- **Operating Goal:** Prioritize durable premium capture, assignment comfort, and downside survivability over maximizing premium

### Market Regime Integration

Before selecting any candidates or trade structures, the agent must read `macro-outlook.md` and determine the current market regime:

| Regime        | Classification                            | Strategy Defaults to Apply                                    |
| ------------- | ----------------------------------------- | ------------------------------------------------------------- |
| Bear          | Declining trend, broad fear, VIX elevated | Defensive Cash-Secured Put + Bear-Resilient Put Credit Spread |
| Sideways      | Range-bound, no clear trend direction     | Core Put-Writing Cadence + Range Put Spread                   |
| Bull/Recovery | Uptrend intact, breadth improving         | Pullback Cash-Secured Put + Bull Put Spread                   |

The regime call governs which two strategy defaults are applied in the output. If the macro outlook is ambiguous or classifies as mixed (e.g., Late Cycle / Stagflation), default to the Bear regime strategy set and note the ambiguity.

### Candidate Stock Rules

Prefer names with:
- Strong balance sheet and durable cash flow
- Institutional support and deep, liquid options chains
- Clear willingness to own if assigned (for any undefined-risk structure)

Disqualify any name with:
- Illiquid options chains (wide bid/ask, low open interest)
- Unresolved existential legal, regulatory, or refinancing risk
- Earnings inside the DTE window for undefined-risk structures (see Pre-Flight Check 4)
- Extreme binary event risk that makes IV structurally elevated for the wrong reasons

If `value-stock-list.md` exists and is fresh, it is the preferred candidate source. Those names have already been scored for balance-sheet quality and moat durability. Pull assignment comfort tiers from that file and supplement with options-specific data.

### Assignment Comfort Tiers

| Tier     | Examples                                                              | Default Structures                    |
| -------- | --------------------------------------------------------------------- | ------------------------------------- |
| High     | Consumer Defensive, large-cap Healthcare, supermajor Energy, Telecom  | Undefined-risk cash-secured puts      |
| Moderate | Quality Industrials, Defense, money-center Banks, Quality Materials   | Staggered entries, conservative delta |
| Low      | High-beta semis, high-multiple software, weak balance-sheet cyclicals | Defined-risk spreads only             |

### Output Format Required

All seven sections must be present in the output file. Do not omit any section:

1. **Market Regime Call and Confidence** — regime classification, supporting evidence from macro-outlook.md, strategy defaults that activate
2. **Candidate Stocks** — 3 to 7 names with assignment comfort tier, earnings date, and IV context for each
3. **Recommended Undefined-Risk Setup** — specific trade for the regime default; include ticker, strike, expiration, delta, premium estimate, and max loss
4. **Recommended Defined-Risk Setup** — specific spread for the regime default; include ticker, strikes, expiration, net credit, max loss, and break-even
5. **Position Sizing and Max Loss** — per-trade sizing as a percentage of account; total portfolio allocation across all positions
6. **Management Plan** — profit-taking target (default: 50% of max profit), roll trigger, stop logic, and early exit conditions
7. **Monitoring Triggers** — macro events, earnings dates, volatility spikes, and sector-level signals that would trigger a review or adjustment

### Per-Trade Required Fields

For every trade specified in the output, include:

| Field                                      | Required |
| ------------------------------------------ | -------- |
| Ticker and sector                          | Yes      |
| Assignment comfort tier                    | Yes      |
| Next earnings date                         | Yes      |
| Trade structure (CSP / put spread / other) | Yes      |
| Strike(s) and expiration                   | Yes      |
| Delta at entry (estimated)                 | Yes      |
| Estimated premium (credit received)        | Yes      |
| Maximum loss                               | Yes      |
| Profit target (close at X% of max profit)  | Yes      |
| Hard stop or roll trigger                  | Yes      |

## Data Collection Method

Execute the following steps in order:

### Step 1 — Read Agent Instructions
- File: `context/trading-agent/trading-options-income-agent.md`
- Purpose: Load the full strategy defaults by regime, assignment comfort tiers, risk rules, and output format.

### Step 2 — Read Macro Outlook
- File: `context/trading-agent/output/macro-outlook.md`
- Extract: regime classification, sector posture (Prefer / Neutral / Avoid), volatility commentary, and rate/macro conditions that affect premium-selling risk.
- Record the macro outlook date in the output frontmatter.

### Step 3 — Load Candidate List
- If `value-stock-list.md` is fresh: read it and extract the top-ranked candidates, their assignment comfort tiers, and any trade structure notes already documented.
- If not available: screen Finviz for high-quality names in macro-preferred sectors, filtered by market cap (at or above $8B), positive FCF, and dividend history.

### Step 4 — Collect Options-Specific Data

For each candidate, collect the following before finalizing trade specifications:

| Data Point                                              | Source                                                    | Why Required                                            |
| ------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------- |
| Next earnings date                                      | Yahoo Finance earnings calendar                           | Undefined-risk disqualifier if inside DTE window        |
| IV Rank or IV Percentile                                | Finviz Elite (authenticated) or Yahoo Finance options tab | Determines whether premium is worth selling             |
| Options chain liquidity (open interest, bid/ask spread) | Yahoo Finance options tab or TradingView                  | Confirms the chain is tradeable                         |
| Key support and resistance levels                       | TradingView                                               | Strike placement below support improves downside buffer |
| Recent news and catalyst risk                           | Yahoo Finance news tab                                    | Confirms no pending binary events outside earnings      |

If IV Rank is not available (unauthenticated Finviz session), note the gap in the output and advise the user to verify IV context before entering trades.

### Step 5 — Apply Regime Strategy Defaults
Match the regime call from Step 2 to the correct strategy pair from the agent instructions:
- Select one undefined-risk default and one defined-risk default for the regime.
- Apply to the top candidates from Step 3, filtered by earnings date (Step 4).
- Specify concrete strikes, expirations, and premiums for each recommended trade.

### Step 6 — Write Output
Save the completed options income trade list to: `context/trading-agent/output/options-income-list.md`

Include required frontmatter (date, time, generated_by, inputs_used). Follow the seven-section output format without omission.
